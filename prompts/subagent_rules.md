# 서브에이전트 공통 규칙

> 발굴 파이프라인의 서브에이전트가 작업 시작 시 가장 먼저 읽는 규칙입니다.
> 메인 에이전트가 0단계에서 이 파일을 `run/rules.md`로 복사합니다.
> 지역·인원·업종 같은 기준값은 이 파일에 적지 않고 `run/discovery_config.json`에서 읽습니다.

---

## 먼저 읽을 것
1. `run/discovery_config.json` — `target`(지역·인원·제외 업종·업종 목록·중점분야), `run`(호출 상한·목표 개수), `verify`(사업자 정보 조회 방법)
2. 메인이 알려 준 **내 담당 출처**의 `how`(조회 방법)와 `run/sources.json`에 적힌 그 출처의 `다음_위치`
3. `run/sources.json`의 `조회불가_사이트` — 시도하지 않는다

## 대원칙
1. **작문 금지.** 도메인·이메일·담당자명을 회사명으로 추측하거나 조합하지 않는다. 원문에 적힌 값만 기록한다. 오탈자도 고치지 않고 `(원문 표기)`를 붙인다.
2. **출처 URL 필수.** 연락처·홈페이지·임직원수·최근활동을 발췌한 상세 페이지 URL을 기록한다.
3. **모르면 비운다.** 확인 못 한 값은 `확인불가`, 홈페이지는 `공식홈페이지 없음`. 이메일이 가려져 있으면(`[email protected]` 등) 확인불가. 단 `mailto:` 링크에 실제 주소가 보이면 쓴다.

## 통과 조건 (모두 충족)
**(a) 지역·업종.** `target.regions`에 사업장 또는 공장이 있는 국내 제조기업. 공장이 다른 지역이면 제외. `target.exclude_business`에 해당하면 제외. 사업자 정보의 업태에 도소매·공사업이 함께 있으면 제조 근거(제조 종목·공장 주소·제품)를 확인한다. 폐업 제외.

**(b) 규모.** 중소기업(`target.exclude_size` 제외). 임직원 수를 확인했으면 `target.max_employees` 이하. 확인 못 했으면 중소기업일 때 포함하고 `확인불가`.

**(c) 연락처.** 둘 중 하나.
- **①** 원문으로 확인된 홈페이지 URL 또는 이메일. 조합·협회·공공 디렉토리·사업자 정보 페이지에 적힌 홈페이지 주소도 인정한다. SSL 오류로 안 열려도 무방하다.
- **②** 홈페이지·이메일이 없거나 안 열려도, 최근 `target.recent_activity_months`개월 안의 날짜가 보이는 활동(채용공고·기사·인증/지원사업 선정·조달/수출/수상·공식 SNS/블로그)이 원문으로 확인되고, 전화 또는 이메일이 하나 이상 원문으로 확인되면 통과. 활동 내용·날짜·URL을 반드시 기록한다. 채용공고는 근무지가 기업 소재지와 같은지 확인한다. 연락처가 하나도 없으면 탈락.

**동일 기업 확인.** 디렉토리의 지역과 사업자 정보의 주소가 다르거나 같은 이름의 회사가 여럿이면 같은 회사인지 확인한다. 못 하면 탈락시키고 사유에 `동일성 확인불가 [재검토가능]`.

**`[재검토가능]` 표시.** 홈페이지·연락처·SSL·접속 불가·검색 불가·동일성 문제처럼 나중에 다시 보면 통과할 수 있는 사유에만 붙인다. 인원 초과·타지역·비제조·상장/계열/해외·중복에는 붙이지 않는다.

**중복 제외.** 후보마다 아래를 실행해 `중복/제외`가 나오면 조사하지 않는다. 여러 후보를 한 번에 넣어 호출 수를 아낀다. 부분일치로 걸렸는데 명백히 다른 회사면 비고에 적고 진행해도 된다.
```bash
python3 run/check_dup.py "기업명" "전화" "이메일" "다른기업명" ...
```

**업종.** `target.industries` 중 실제 제품 기준으로 하나를 고른다. 맞는 게 없으면 `기타`로 두고 비고에 이유를 적는다. **중점분야**는 `target.focus_tags`에 실제 제품이 해당할 때만 그 이름을 적는다(일반 부품이면 `아니오`).

## 호출·분산 규칙
- 도구 호출 상한은 `run.agent_call_limit`회(WebFetch·WebSearch·Read·Write·Bash 등 모든 호출 포함). 호출 수를 세면서 진행하고, `run.agent_stop_saving_at`회에 도달하면 새 후보 조사를 멈추고 결과 저장만 한다.
- 통과 목표는 `run.agent_target_pass` 범위, 최대 `run.agent_max_pass`개. 한 목록 페이지·한 시군구·한 업종에 몰지 말고 분산한다(같은 시군구 4개, 같은 업종 5개 이하 권장).
- 기업 1곳 검증은 가능하면 2~3회 호출로 끝낸다: 디렉토리 상세 → `verify.company_lookup`. 목록만 보고 탈락이 분명하면(업종·규모·지역) 조회하지 않는다.
- WebSearch는 꼭 필요할 때만 쓴다(신규 디렉토리 발굴 담당 외에는 3회 이하). robots·SSL·403으로 실패한 사이트는 우회하지 말고 `new_blocked`에 적는다. Bash로는 외부 웹에 접속할 수 없다(WebFetch 사용).
- 중간 결과를 자주 저장하지 말고 마지막에 1~2회 저장한다.

```json
{
 "agent": "A",
 "calls_used": 0,
 "passed": [{
   "기업명": "", "시도": "", "시군구": "", "업종": "", "중점분야": "아니오",
   "임직원수": "N명 또는 확인불가", "전화": "", "이메일": "", "홈페이지": "",
   "주요사업": "", "최근활동": "YYYY.MM 내용 (URL) — 조건②면 필수, 아니면 빈칸",
   "통과조건": "① 또는 ②", "재검토": "예/아니오", "예비후보": "예/아니오",
   "출처사이트": "발굴 출처(원래 출처)", "출처URL": ["..."], "담당자": "원문에 있으면",
   "제안안": "이 회사 업종·제품에 맞는 제안 1문장 (config의 team.proposal_hint 참고)",
   "비고": "컨택 전 확인할 점"
 }],
 "rejected": [{"기업명": "", "사유": "", "출처": "URL"}],
 "next_position": "다음 회차가 이어서 조회할 정확한 위치(URL·페이지 번호·미처리 후보명)",
 "new_blocked": [],
 "new_sources": [{"이름": "", "URL": "", "형식": "", "다음위치": ""}]

```
- 모든 값은 원문 기준. 전화가 여러 개면 대표번호 1개.
- 재검토 대상이 또 탈락하면 사유를 `재검토:`로 시작한다.
- 메인에게 돌려줄 마지막 응답은 3줄 이내: 통과 수, 탈락 수, 호출 수, 파일 경로.
