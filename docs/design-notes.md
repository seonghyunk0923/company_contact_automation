# 설계 노트 — 왜 이렇게 바뀌었나

발굴 자동화는 2026년 9월 말부터 10월 초까지 여러 번 고쳐 쓰였고, 10월 말에 다른 팀이 쓸 수 있는 템플릿으로 정리했습니다. 1~9는 v1([`prompts/archive/00_…`](../prompts/archive/00_discovery_v1_2026-09.md))에서 운영판([`01_…`](../prompts/archive/01_discovery_pipeline_2026-10.md))으로 오면서 부딪힌 문제와 결정, 10은 템플릿화 때의 결정입니다.

## 1. "정확히 50개"를 버리고 "최대 50개"로

**v1:** 검증에서 하나라도 탈락하면 즉시 재탐색해 통과 기업 수를 정확히 50개로 맞추는 보충 루프.

**문제:** 중소기업은 홈페이지·연락처가 불완전한 곳이 많아 탈락률이 높았습니다. 50개를 채우려고 탐색이 끝없이 길어졌고, 뒤로 갈수록 기준을 느슨하게 적용하는 경향이 생겼습니다.

**결정:** 서브에이전트별 도구 호출 상한(60회, 55회부터는 저장만)을 두고, 모인 후보에서만 최대 50개를 고릅니다. 모자라면 부족 수와 이유를 보고합니다. 실행 비용과 시간이 예측 가능해졌습니다.

## 2. 홈페이지 "정상 접속" 요구 완화 → 조건 ① / ②

**문제:** 중소 제조기업 홈페이지는 SSL 인증서 오류, 도메인 만료, 자체 서명 인증서가 흔합니다. "정상 접속"을 요구하니 실제로 운영 중인 회사가 대량 탈락했습니다.

**결정:**
- 조건 ①: 공공·협회 디렉토리나 사업자 정보 페이지에 **원문으로 적힌** 홈페이지·이메일이면 인정(안 열려도 무방).
- 조건 ②: 홈페이지·이메일이 없어도 최근 12개월 이내 날짜가 있는 활동(채용공고·기사·인증 등)과 전화·이메일 하나가 원문으로 확인되면 통과. 활동 날짜와 URL을 반드시 기록.

## 3. 작문 금지 원칙

**문제:** 모델이 회사명으로 도메인이나 `info@회사명.co.kr` 같은 이메일을 "그럴듯하게" 만들어 넣을 위험이 있습니다. 컨택 리스트에서 가장 치명적인 오류입니다.

**결정:** 모든 연락처는 원문 값만, 출처 URL 필수. 확인 못 한 값은 `확인불가`. 오탈자도 고치지 않고 `(원문 표기)`를 붙입니다.

## 4. 회차 간 상태를 진행기록 JSON으로

**문제:** 예약 작업은 매번 새 세션에서 시작하므로 어제 어디까지 봤는지 모릅니다. 같은 목록 페이지를 반복 조회하거나, 이미 탈락시킨 기업을 다시 검증하는 낭비가 생겼습니다.

**결정:** `탐색진행상황.json`에 출처별 다음 조회 위치, 조회불가 사이트, 탈락기업(사유·일자), 예비후보, 마지막 번호를 기록하고 매 회차 끝에 갱신합니다. 구조는 [`data/README.md`](../data/README.md) 참고.

## 5. 서브에이전트 5개로 분할

출처별로 서브에이전트를 나눠 병렬로 돌립니다(워크넷 강소기업 / 인천기업정보 / 메인비즈 / 신규 디렉토리 발굴 / 예비후보·재검토). 한 에이전트가 모든 출처를 도는 것보다 빠르고, 출처마다 다음 조회 위치를 따로 이어갈 수 있습니다.

메인은 결과를 합친 뒤 **상한**을 적용해 한쪽으로 쏠리지 않게 고릅니다: 한 출처 ≤ 12, 한 시·도 ≤ 20, 인천 ≤ 12, 한 시·군·구 ≤ 5, 한 업종 ≤ 10, 출처 4곳 이상. 상한으로 빠진 통과 기업은 버리지 않고 예비후보로 넘겨 다음 회차에 먼저 씁니다.

## 6. 2026-10-01 정비 (실행 전 점검에서 나온 9건)

| 문제 | 조치 |
|---|---|
| 60회 상한으로는 출처당 13~15개 목표가 불가능 | 에이전트당 목표 10~12개로 조정 |
| 충북 우선 조사 로직이 진행기록 메모에 남아 있음 | 메모 삭제 규칙 추가 |
| 쓸 수 없는 알림 도구를 호출하도록 적혀 있음 | 채팅 보고만 남김 |
| 소진된 출처가 계속 담당으로 배정됨 | 활성 출처에서 제외 |
| 재검토 27개를 한꺼번에 돌렸으나 전부 실패 | 회차당 재검토 최대 5개 |
| 서브에이전트마다 원본 명단(~1,400행)과 탈락목록(~400개)을 각자 읽음 | 0단계에서 `exclude_names.txt` 한 파일로 정리 ([`prep_exclude.py`](../scripts/prep_exclude.py)) |
| 검증된 예비후보가 활용되지 않음 | 서브에이전트 E가 우선 처리 |
| 목록만 봐도 비제조인 기업까지 사업자 조회 | 목록 단계에서 건너뜀 |
| 50개 미만일 때 행동이 정의되지 않음 | 추가 탐색 없이 부족 수·이유 보고 |

## 7. 중복 확인 오탐: 짧은 이름

**문제:** `(주)일`, `(주)케이`가 기존 명단에 있어서, 정규화 후 부분일치로 `주식회사 동일공사`, `케이아이산업개발` 같은 무관한 회사가 중복으로 걸러졌습니다.

**결정:** 부분일치는 정규화 이름이 **양쪽 모두 3자 이상**일 때만 적용합니다([`normalize.py`](../scripts/normalize.py)의 `names_match`). 완전일치와 전화·이메일 일치는 그대로입니다.

## 8. 시트 직접 쓰기 → 엑셀 산출 + Apps Script 반영

**v1:** Claude가 컨택 시트 맨 아래에 직접 50행을 추가.

**결정:** Claude는 4개 시트짜리 엑셀(추가분·검증정보·탈락·요약)만 만들고, 컨택 시트 반영은 Apps Script(`ImportRows.gs`)가 합니다.
- 팀원들이 함께 쓰는 시트를 에이전트가 직접 건드리지 않습니다. 반영 전에 엑셀을 열어 검증정보·탈락 사유를 볼 수 있습니다.
- 번호 재부여와 중복 기업명 건너뛰기를 반영 시점에 한 번 더 합니다. 발굴 쪽 중복 확인을 빠져나간 행도 여기서 걸러집니다.
- 반영한 파일은 `반영완료` 폴더로 옮겨 두 번 붙지 않게 합니다.

메일 쪽(`ContactAutomation.gs`)도 같은 원칙으로, 시트 기록과 초안 작성까지만 하고 발송은 사람이 합니다.

## 9. 이번 구조의 한계

- **서울 후보 부족:** 서울은 사무실형 주소가 많아 "공장 소재" 확인에서 자주 탈락합니다. 서울 통과 수가 적으면 경기·인천 상한에 걸려 50개를 못 채웁니다(10/1 회차 39개, 10/2 회차 37개).
- **robots·SSL 차단:** 공공 디렉토리 상당수가 자동 조회를 막아 둡니다. 조회불가 목록이 50곳 가까이 쌓였습니다.
- **사업자 정보 사이트 의존:** 검증 대부분이 한 사이트의 사업자 상세 페이지에 기대고 있어, 그 사이트 구조가 바뀌면 영향이 큽니다.

## 10. 다른 팀이 쓰는 템플릿으로 (2026-10-24)

운영판은 우리 팀의 진행 상황·출처·지역·메일 문구에 묶여 있었습니다. 다음 팀이 쓰려면 아래를 바꿔야 했습니다.

| 문제 | 결정 |
|---|---|
| 기준값(지역·인원·업종·상한·출처)이 프롬프트 본문에 있음 | `discovery_config.json` 한 파일로 모으고, 프롬프트와 서브에이전트 규칙은 이 파일을 읽게 함 |
| 메일 문구·팀명·날짜가 Apps Script 코드에 섞여 있음 | `Config.gs`로 모으고 본문을 `{이름}` 템플릿으로. 값이 비면 그 줄을 빼는 규칙으로 조건부 줄(팀원 연락처, 제안주제)을 처리 |
| 문구를 안 고친 채 실행하면 이전 팀 이름으로 초안이 생김 | `TEMPLATE_REVIEWED`가 true가 되기 전에는 테스트 실행만 허용 |
| 개인 연락처·파일 ID가 코드에 있음 | 스크립트 속성으로. 비개발자도 입력할 수 있게 **⚙ 초기 설정** 메뉴에서 차례로 묻도록 |
| Apps Script가 두 프로젝트로 나뉘고 함수 이름이 겹침 | 한 프로젝트·파일 4개로 합치고, 테스트에서 파일 간 함수 이름 중복을 검사 |
| 선정·엑셀·기록 갱신을 Claude가 매번 스크립트를 새로 짜서 처리 | 저장소의 Python 스크립트로 고정. Claude는 탐색·검증·원문 재확인만 하고, 같은 입력이면 같은 엑셀과 같은 기록이 나오게 함 |
| 새 팀은 진행기록이 없음 | `init_records.py`가 설정의 출처 목록으로 빈 진행기록을 만듦. 첫 실행 때 프롬프트가 자동으로 호출 |
| 회신에서 우리 메일 인용문을 지우는 문구가 우리 본문에 맞춰 하드코딩 | 템플릿 고정 문장에서 조각을 자동으로 뽑고, 팀이 추가 구절을 설정에 적을 수 있게 함 |
