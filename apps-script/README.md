# Apps Script — 컨택 시트·Gmail 연동

컨택 시트(Google 스프레드시트)에 붙여 쓰는 스크립트입니다. 파일 4개를 한 프로젝트에 넣으면 시트에 **🤖 컨택 자동화** 메뉴가 생깁니다. 설치 순서는 [`SETUP.md` 1단계](../SETUP.md#1단계-컨택-시트와-메일-자동화-google)를 보세요.

| 파일 | 내용 | 고치나? |
|---|---|---|
| [`Config.gs`](Config.gs) | 팀명·메일 제목·본문·검색 시작일 등 팀별 설정 | **예** |
| [`Setup.gs`](Setup.gs) | 시트 메뉴, 초기 설정(머리글·Drive 폴더·연락처 입력), 설정 점검 | 아니오 |
| [`ImportRows.gs`](ImportRows.gs) | 추가분 시트를 컨택 시트 맨 아래에 붙임 | 아니오 |
| [`ContactAutomation.gs`](ContactAutomation.gs) | Gmail 발송·답장 대조, 감사·협력 요청 초안 작성 | 아니오 |
| [`appsscript.json`](appsscript.json) | 시간대(서울)·런타임 설정. clasp로 올릴 때만 필요 | 아니오 |

**메일은 자동 발송하지 않습니다.** 초안은 Gmail 임시보관함에만 만들고, 발송은 사람이 합니다.

## 메뉴

| 메뉴 | 하는 일 |
|---|---|
| ⚙ 초기 설정 | 머리글 16열 생성, `기업컨택_추가분`·`반영완료` 폴더 생성, 팀장 연락처·참조 메일·제안서 파일 입력 |
| ✅ 설정 점검 | 필요한 값이 다 있는지, 메일 문구를 확인했는지 ✅/❌로 보여 줌 |
| 📥 추가분 지금 반영 | 추가분 폴더의 새 시트를 바로 반영 |
| ⏰ / ⏸ 추가분 자동 반영 | 매시간 자동 반영 켜기·끄기 |
| ▶ 메일 자동화 전체 실행 | Phase 1 → 2 → 보고 |
| 🧪 테스트 실행 | 시트 기록·초안 생성 없이 할 일만 로그에 기록 |
| 📋 진행 상태 | 진행 중인 실행 또는 마지막 결과 |
| ⏹ 중단·초기화 | 진행 상태를 지우고 다음 실행을 처음부터 |

## 설정값이 저장되는 곳

| 어디 | 무엇 | 왜 |
|---|---|---|
| `Config.gs` | 팀명, 메일 문구, 검색 시작일, 키워드 | 팀마다 다르지만 공개돼도 되는 값 |
| 스크립트 속성 (초기 설정에서 입력) | 팀장 이름·연락처·이메일·직함, 참조 이메일, 제안서 파일 ID, 추가분 폴더 ID | 개인 연락처·파일 위치라 코드(=GitHub)에 남기지 않음 |

스크립트 속성은 Apps Script 편집기의 **⚙ 프로젝트 설정 → 스크립트 속성**에서도 보고 고칠 수 있습니다.

| 키 | 값 |
|---|---|
| `LEADER_NAME`, `LEADER_PHONE`, `LEADER_EMAIL`, `LEADER_TITLE` | 메일 본문의 팀장 문의처, 감사 메일 서명 |
| `CC_EMAIL` | 모든 초안의 참조(선택) |
| `PROPOSAL_FILE_ID` | 첨부할 제안서 PDF (`ATTACH_PROPOSAL: false`면 불필요) |
| `FOLDER_ID` | 추가분 폴더 (초기 설정이 자동으로 채움) |

## 안전장치

- `Config.gs`의 `TEMPLATE_REVIEWED`가 `false`면 실제 실행을 막습니다. 문구를 고치지 않은 채 다른 팀 이름으로 초안이 만들어지는 것을 막기 위해서입니다.
- 실제 실행 전에 필수 설정값·제안서 파일·머리글·템플릿 형식을 확인하고, 문제가 있으면 목록을 보여 주고 멈춥니다.
- 쓰기 대상 열(`메일답장여부`·`컨택일자`·`초안작성여부`)이 이름에 `전화`가 들어간 열과 겹치면 바로 멈춥니다.
- 사람이 `메일답장여부`에 직접 쓴 문장은 덮어쓰지 않습니다(`OVERWRITE_MANUAL_REPLY: false`).
- 임시보관함에 같은 수신자의 초안이 이미 있으면 새로 만들지 않고 `O`만 표시합니다.
- 거절 회신 이후 이미 답장을 보냈거나 감사 초안이 있으면 감사 초안을 또 만들지 않습니다.

## 메일 자동화가 하는 일

**Phase 1 — 발송·회신 대조.** 시트에서 담당자 이메일이 있는 행을 20행씩 읽고, 그 주소(회사 도메인이면 도메인 전체)로 주고받은 메일을 찾습니다.
- 우리가 보낸 메일이 있으면 `컨택일자`와 `초안작성여부`를 채웁니다.
- 회신은 아래처럼 분류해 `메일답장여부`에 쓰고, 판정 근거(보낸 사람·본문 앞부분)를 셀 메모로 남깁니다.
- 거절이면 감사 답장 초안을 만듭니다.

**Phase 2 — 협력 요청 초안.** `팀원명`이 있고, 담당자 이메일이 있고, `초안작성여부`가 빈 행마다 제안서를 첨부한 초안을 만들고 `O`를 표시합니다. 회신 기한은 실행일 기준 `REPLY_BUSINESS_DAYS`영업일 뒤로, 공휴일 캘린더를 반영합니다.

**Phase 3 — 보고.** `자동화_실행로그` 탭에 행별 처리 내역을 남기고 요약을 알림창으로 띄웁니다.

Apps Script는 1회 실행이 6분으로 제한되므로, 4분 30초가 지나면 진행 위치를 저장하고 1분 뒤 시간 트리거로 이어서 실행합니다(최대 60회). 오류가 연속 3번 나면 멈추고 로그에 남깁니다.

### 회신 분류

본문에서 인용된 우리 메일(`Config.gs`의 `COOP_BODY` 고정 문장과 `EXTRA_TEMPLATE_NOISE`)을 지운 뒤 키워드 점수로 판정합니다.

| 상태 | 판정 |
|---|---|
| 거절 | 거절·불가·어렵·여력이 없 등 점수 2 이상이고 수락보다 높음 |
| 수락 | 참여하겠·미팅 가능·방문 가능·일정 조율 등 점수 2 이상이고 거절보다 높음 |
| 지연 | 검토 후·내부 논의·추후 회신 등 |
| 지연(부재중) | 자동 응답·부재중 메일 |
| 반송 / 반송(일부) | 메일 서버 반송. 등록된 주소 전부 또는 일부 |
| 회신(확인필요) | 위 어디에도 해당하지 않음 — 사람이 읽고 판단 |

판정은 참고용입니다. 애매한 회신은 메모를 보고 사람이 고쳐 쓰면, 그 값은 이후 덮어쓰지 않습니다.

## 추가분 반영이 하는 일

추가분 폴더에서 이름이 `기업컨택_리스트_추가분_`으로 시작하는 **Google 시트**를 이름순으로 열어, 첫 번째 탭의 행을 컨택 시트 맨 아래에 붙입니다.
- 번호(A열)는 컨택 시트의 마지막 번호 다음부터 다시 매깁니다.
- 기업명(D열)이 이미 있으면 건너뜁니다. (주)·주식회사·공백 차이는 같은 이름으로 봅니다.
- 반영한 파일은 `반영완료` 폴더로 옮깁니다.
- `.xlsx` 파일은 읽지 않습니다. Drive의 업로드 변환을 켜거나, 파일을 Google 시트로 열어 변환본을 만드세요.

## 개발자용

- clasp로 관리하려면 이 폴더에서 `clasp create --type sheets` 또는 기존 스크립트 ID로 `clasp clone` 후 `clasp push`.
- 순수 함수(템플릿 렌더링·회신 분류·인용문 제거 등)는 Node에서 테스트할 수 있습니다: `node --test tests/apps_script.test.js`
- 원래는 추가분 반영과 메일 자동화가 별도 스크립트였고 둘 다 `norm_`이라는 이름의 다른 함수를 정의하고 있었습니다. 한 프로젝트로 합치면서 반영 쪽을 `normName_`으로 바꿨고, 테스트가 파일 간 함수 이름 중복을 검사합니다.
