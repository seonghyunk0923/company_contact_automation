# 발굴 설정 (`discovery_config.json`)

[`discovery.example.json`](discovery.example.json)을 복사해 `discovery_config.json`으로 이름을 바꾸고 claude.ai Project에 올립니다. `_`로 시작하는 키는 설명이라 지워도 됩니다. JSON이라 쉼표·따옴표가 하나라도 틀리면 읽히지 않으니, 고친 뒤 [JSON 검사기](https://jsonlint.com) 같은 곳에 붙여 넣어 확인하면 안전합니다.

## team — 팀 정보

| 키 | 뜻 | 쓰이는 곳 |
|---|---|---|
| `contest` | 공모전 이름 | 보고 |
| `team_name` | 팀명 | 보고 |
| `job_title` | 직무명 | 엑셀 `직무명` 열 |
| `default_contact_title` | 담당자 이름을 못 찾았을 때 쓸 호칭 | 엑셀 `담당자명/직급` 열 |
| `proposal_hint` | 회사별 '제안안' 한 문장을 쓸 때의 방향 | 엑셀 `기업소개 및 제안주제` |

## target — 어떤 기업을 찾나

| 키 | 뜻 |
|---|---|
| `regions` | 사업장 또는 공장이 있어야 하는 시·도 |
| `max_employees` | 임직원 수 상한(확인됐을 때만 적용) |
| `exclude_business` | 제외할 업태(도소매, SW 등) |
| `exclude_size` | 제외할 규모(중견·대기업·상장사 등) |
| `industries` | 업종 분류 목록. 결과의 `업종`은 이 중 하나로 적힘 |
| `focus_tags` | 우선할 분야(예: 반도체·이차전지). 해당하면 같은 순위 안에서 먼저 뽑힘 |
| `recent_activity_months` | 조건②(홈페이지·이메일 없이 최근 활동으로 통과)의 기간 |

## run — 한 번 실행의 크기

| 키 | 뜻 |
|---|---|
| `max_per_run` | 1회 최대 선정 수 |
| `agent_call_limit` | 서브에이전트 하나가 쓸 수 있는 도구 호출 수 |
| `agent_stop_saving_at` | 이 호출 수에 도달하면 새 후보 조사를 멈추고 저장 |
| `agent_target_pass`, `agent_max_pass` | 서브에이전트 하나의 통과 목표 범위와 최대 |
| `recheck_per_run` | 1회에 재검토할 탈락 기업 수 |
| `spot_check` | 최종 선정 중 원문을 다시 확인할 개수 범위 |

호출 수를 늘리면 더 많이 찾지만 실행 시간과 사용량이 늘어납니다. 서브에이전트 5개 × 60회가 1회 약 10~20분이었습니다.

## caps — 한쪽으로 쏠리지 않게 하는 상한

| 키 | 뜻 |
|---|---|
| `per_source` | 한 출처(디렉토리)에서 최대 |
| `per_region` | 한 시·도에서 최대 |
| `per_region_override` | 특정 시·도만 다른 상한(예: `{"인천": 12}`) |
| `per_district` | 한 시·군·구에서 최대 |
| `per_industry` | 한 업종에서 최대 |
| `min_sources` | 서로 다른 출처가 최소 몇 곳이어야 하는지(보고에서만 확인) |

상한으로 빠진 통과 기업은 버리지 않고 **예비후보**로 넘어가 다음 회차에 먼저 재확인됩니다. 결과가 목표보다 계속 적고 보고의 "빠진 이유"가 상한이라면 상한을 늘리세요.

## sources — 어디서 찾나

출처 하나마다 서브에이전트 하나가 붙습니다(최대 5개).

| 키 | 뜻 |
|---|---|
| `id` | 서브에이전트 이름(A, B, …). 결과 파일 `result_<id>.json` |
| `name` | 출처 이름. 진행기록에서 이 이름으로 다음 조회 위치를 저장 |
| `enabled` | `false`면 이번 실행에서 쓰지 않음 |
| `type` | 비우면 일반 디렉토리. `discover`는 새 디렉토리 찾기, `reserve`는 예비후보·재검토 담당 |
| `how` | 서브에이전트에게 주는 조회 방법. URL 형식, 목록·상세 구조, 거를 기준을 구체적으로 |
| `max_pass` | 참고용 통과 목표 |

**새 출처를 추가할 때:** 업종 협동조합·협회 회원사 목록, 지자체 기업 디렉토리, 산업단지 입주기업 목록처럼 **목록이 페이지로 나뉘어 있고 기업명·지역·업종이 보이는 곳**이 잘 맞습니다. `how`에 목록 URL의 페이지 번호 형식과 상세 페이지에서 볼 항목을 적어 주세요. 신규 디렉토리 담당(`discover`)이 찾은 곳은 진행기록 `출처별_진행`에 "신규"로 쌓이니, 쓸 만한 것을 골라 `sources`에 옮기면 됩니다.

기본 예시의 출처(워크넷 강소기업, 인천기업정보, 메인비즈)는 2026년 기준으로 동작했습니다. 사이트 구조가 바뀌면 `how`를 고쳐야 합니다.

## verify — 기업 검증 방법

`company_lookup`은 디렉토리에서 찾은 기업의 전화·홈페이지·종업원수·업태·폐업 여부를 확인할 때 쓰는 사업자 정보 조회 방법입니다.

## files — Project 안의 기록 파일 경로

진행기록·기존기업명단·누적목록을 Project 어디에 둘지 정합니다. 기본값(`claude/…`)을 바꿀 이유는 거의 없습니다.
